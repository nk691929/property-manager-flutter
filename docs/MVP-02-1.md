# MVP 2.1: Property photos

## Built
- Up to 10 photos per listing (JPEG/PNG/WebP, 5 MB each), stored in Supabase Storage
- Agents add (camera or gallery), remove and set the cover while a listing is draft or rejected
- Cover thumbnail on every card; swipeable gallery with counter on the detail screen
- Deleting a draft removes its files
- DB: `property_photos`, bucket `property-photos`, storage and table RLS,
  photo-limit trigger (`supabase/migrations/0003_property_photos.sql`)

## Test plan
- Unit: photo rules (type sniffing, limits, positions), use cases (permissions,
  edit lock, limits, delete ordering), JSON parsing of embedded photos
- Database: six SQL checks run in the Supabase SQL editor
- Manual: upload, cover, remove, lock, client gallery, delete cleanup, offline failure

## Known limitations
- Public bucket: anyone with a URL can open the image
- No automated test for the Supabase storage calls or the photo manager widget
- One photo per pick; no drag-to-reorder, full-screen zoom, or server thumbnails
- Admins have the database rights but no photo UI yet
- HEIC/HEIF images are not accepted (iOS re-encodes picked images as JPEG when resized; unverified without a Mac)
- Android may restart the app while the camera is open; the pending photo is lost
- Orphan files are possible if a cleanup delete fails (logged only)
- Photo section is disabled in offline demo mode
